How ansible work:
Need to have one master where ansible is installed then need to have all client machine where we run our modules.no need to have ansible installed on client.just ansible master push module to all client and run it.it will run all module in  parallel.Ansible follow push mech ie from master its just push all the module to client and its agent less since we dont have ansible installed in all client mahine.by default ansible run 5 client server in parallel.if we want to change that we can got ansible.cfg and make forks = any number.if we set 1 it will run in sequntial order.by default its set as 5 and if we have 15 client server then it will run in 3 groups parallely for all 15 server.
While running adhoc cmd or play book, ansible master push all module to all client server, in all client all module run inside home directory of our user ie ansible inside that .ansible directory inside that temp directory and inside it will create python program and run

Ansible facts:
Gathering the information about client machine is called facts or variable.to gather info we need to use setup command.No need to write setup module in playbook,playbook when it run it will automatically gather info abt client machines

Two types of fact are there
Default fact -  getting the info by giving setup cmd
custom fact - getting additional info of client machine for  doing that need to create custom facts in client machine , so master machine can see that custom details

Custom Facts:
getting additional info of client machine, for  doing that need to create custom facts in client machine , so master machine can see that custom created details
Additional details means just consider on all client machine we need to get version of git and httpd but for doing that we can write adhoc cmd as well, but we have to write 2 adhoc cmd individually to see , but if we write custom fact file we can see both in single adhoc cmd by calling setup.the fact may be in shell or python .while running the setup cmd we can able to custom fact op in master machine along with orginal details.to only see the custom file output need to use filter=ansible_local.
Steps to write custom facts:
1)need to create folder structure below in all client machine
/etc/ansible/facts.d
2)inside fact.d can create any number of .fact file and inside .fact file we can create code using python or shell but file extension should be .fact
3)output of .fact file should be json
4)file should have execution permission.
below is the example written shell script and saved as customfact.fact which placed in client machine /etc/ansible/facts.d

Ignoring errors:
Below play book used command module to navigate to the path and register argument is store the op of command op
ignore_errors: yes - usually if we have multiple task ,if one task fail below task wont run , to make even one task fail all below task to run need to use ignore_erors as true
Play book:
---
 - name: ignore errors
   hosts: all
   tasks:
   - name: open the folder1
     command: "ls /root/testing"
     register: op1
     ignore_errors: true
   - name: open folder2
     command: "ls /root/test"
     register: op2
     ignore_errors: true
   - name: open folder2
     command: "ls /root/script"
     register: op3
     ignore_errors: true


Block:
block is used to group the comman action for the multiple task. for above playbook we are using ignore error on each task so what we can do is we can create one common block and keep all task inside the block and use common ignore error for that block , so it applicable to all task inside blocks.
Playbook:
---
 - name: blocks
   hosts: all
   tasks:
   - block:
      - name: open the folder1
        command: "ls /root/testing"
        register: op1
      - name: open folder2
        command: "ls /root/test"
        register: op2
      - name: open folder2
        command: "ls /root/script"
        register: op3
     ignore_errors: true
~

Tags:
If we have multiple tasks in your play book and want to run some particular or few thing only we can handle this by using Tags

Playbooks:

---
 - name: Restarting the server
   hosts: client
   become: true
   tasks:
   - name: install httpd
     tags: install
     yum:
       name: httpd
       state: latest
   - name: Restarting the httpd  service
     tags: httpd
     service:
       name: httpd
       state: restarted
   - name: Checking Service Status
     tags: httpd, status
     shell: service httpd status
     register: serverstatus
   - name: Show Service status
     tags: debug
     debug:
       msg: "Service is Up and Running"
     when: serverstatus.rc | int == 0
This help us to see list of tags we mentioned in playbook
ansible-playbook --list-tags tags.yaml
This help us to run particular tags in play book0
ansible-playbook --tags install tags.yaml - only run install tag section ansible playbook
ansible-playbook --tags "install,httpd" tags.yaml  - only run install and httpd section alone in playbook
